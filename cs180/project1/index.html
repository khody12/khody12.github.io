Images of the Russian Empire

CS180 Project 1

Project Overview

This project involved restoring early 20th-century color photographs from the Russian Empire. The images were originally captured by Sergei Mikhailovich Prokudin-Gorskii as three separate black-and-white glass plate negatives using red, green, and blue filters. He won the Tzar's special permission to travel across the empire and take color photographs of everything he saw.

His idea was to record three exposures of every scene onto a glass plate using a red, a green, and a blue filter. Even though there was no way to print color photographs until much later.

By digitally overlaying and aligning these three channels, the original color and breathtaking beauty of the scenes can be restored, offering a vivid glimpse into a world over a century old.

Naive Alignment

The naive solution to this problem is to just take each image, make sure it's the same shape, and then layer the channels over each other. But as we can see, this doesn't look quite right.

This is because Sergei couldn't keep the camera absolutely perfectly steady as he changed the filters. Considering this was the early 1900s, some small movements are to be expected. So there are some alignment issues that will need to be rectified.

Result of Naive Alignment (Significant Ghosting)

Single-Scale Alignment

A way to align the color channels is to have a base channel, in my case blue, and compare it with the red and green channel and try to minimize the difference between the two images by comparing the pixels in some range like [-15, 15].

This would be accomplished by keeping one channel steady while shifting the other channel and measuring the sum of the distance between their values using Normalized Cross-Correlation (NCC) or L2 norm.

Essentially we would try shifting the red/green channel say 5px right, 5px up. If this has a lower displacement (i.e. the values are closer), then they should be more aligned. I used the L2 norm to accomplish this. Additionally, I have cropped the borders by about 10% to eliminate the incredibly noisy borders.

Result of Single-Scale Alignment (Much sharper)

Image Pyramid Alignment

Single-scale alignment works great for smaller images that don't have tons of pixels. When you move to larger images, you may need to iterate through larger pixel displacements like [-30, 30] in order to ensure alignment.

One way to fix this is to use an image pyramid. Basically you take the original image and downsample to half the size. You can then run the same Single-Scale alignment method, just on a smaller image. You take the height and width displacements from the smaller image and use those points as a starting point for a single scale alignment on the larger image. This enables us to use a smaller search window, and drastically save on compute time.

Ultimately, the idea would be to use recursion to take an original image, make some number of iterations of downsampling depending on the original size of the image. Then proceed through a series of iterations from coarse to fine. Each iteration would give a new height and width displacement value as a starting point for the next larger image's displacement search. Each image would be going through a relatively smaller window of possible displacements like [-5, 5] instead of [-15, 15] or larger, massively saving on compute time.

High-res alignment using Image Pyramid

Problems with Aligning Using Pixel Intensity

One major problem with aligning by pixel intensity is that there are occasions where the brightness values of different color channels doesn't match up. This would cause major issues in alignment.

Look at what happens with this photo of the last Emir of Bukhara, Sayyid Mir Muhammad Alim Khan, where the intensities of red, green and blue are quite different.

Alignment failure due to differing channel intensities

Using Edge Detection

Rather than using pixel intensities to align photos, we can use edge detection.

Edge detection works by looking at the steepness of the intensity change in each direction. Larger intensity changes indicate that there is likely an edge there, leading there to be a higher value at that pixel in the edge map.

We can use these edge maps to more reliably align channels because while color intensities may vary like in the case of the Emir, edges should stay much more consistent.
